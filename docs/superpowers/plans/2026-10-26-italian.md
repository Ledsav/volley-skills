# Italian Interface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every piece of app chrome available in Italian, locale-aware dates and numbers, gender-agreeing labels, behind a release flag, without changing a single English test assertion.

**Architecture:** In-house typed catalogs: `src/i18n/en/<feature>.ts` is the source of truth; `src/i18n/it/<feature>.ts` `satisfies` the English types, so a missing key fails `tsc -b` (and the build). `useT()` / `getT()` return the active catalog; pure modules return codes and the UI maps them to text. Feature folders convert one at a time with identical English text, so tests stay green throughout. `ITALIAN_ENABLED` keeps Italian unreachable until the coach review signs off.

**Tech Stack:** React 18 + TypeScript (strict), `Intl` (`DateTimeFormat`, `NumberFormat`, `PluralRules`), Vitest + Testing Library, Firestore rules tests.

**Spec:** `docs/superpowers/specs/2026-10-20-volley-skills-italian-design.md` (read it; §5 table, §5b gender and §6 glossary are referenced, not repeated). Build **after** `docs/superpowers/plans/2026-10-26-dvw-import.md` lands, so the import's screens convert with everything else.

## Global Constraints

- Branch: `feature/italian` from `main` (after the DataVolley import merges).
- No i18n library. No runtime machine translation. User content and stored codes (`Level`, `ObjectiveStatus`, skill/grade codes, exercise categories, positions) are never translated in Firestore; they are labelled at display time.
- English is the default and the test language: `tests/setupTests.ts` forces `en`. Converting a folder must not change any English string, so its existing tests pass unchanged.
- Italian catalogs: `export const <feature> = { … } satisfies Catalog['<feature>']`, loaded by dynamic import only when Italian is active; English bundled.
- Plurals go through `plural(n, { one, other })` (`Intl.PluralRules`); remove the 10 hand-written `n === 1 ?` and the local `plural` helpers as their folders convert.
- Gender: `type Gender = 'women' | 'men' | 'mixed'`; catalog entries naming or describing players take `g: Gender`; English ignores it; `mixed` uses the paired form ("Palleggiatore/trice") or a neutral rewording.
- Volleyball terms exactly as the glossary in spec §6 (e.g. Serve = **Battuta**, Block = **Muro**, Set (skill) = **Alzata**); grade symbols `# + ! - / =` shown unchanged.
- `ITALIAN_ENABLED = false` in `src/i18n/locales.ts` until the operator flips it (Task 13). While false: the resolver never returns `it`, the Settings row, public-page toggle and the club `locale` option `it` are hidden. Dev builds may force `?lang=it`.
- SEO meta, `index.html`, manifest stay English; page titles keep the ` · Volley Skills` suffix.
- Text-scout protocol (the grade/skill table sent to the model) stays English codes and labels.

## Review Focus

1. **A stored value written in Italian.** A select whose option *values* become translated labels (level, status, position, category) would write "Avanzato" to Firestore. Each conversion task's tests assert the stored value stays the English code (Task 3 pins the label maps; Task 7 and Task 8 assert the saved payload).
2. **Italian text 15–25% longer breaks tight UI.** Scout buttons, chips, KPI tiles, the bottom bar and awards slides. Task 12 renders them in Italian at 375 px and asserts no horizontal overflow on the scout grid and bottom bar.
3. **A date still following the browser instead of the app language.** Any leftover `toLocaleDateString(undefined, …)`. Task 2 adds a test that greps `src` for `toLocaleDateString(undefined` / `toLocaleString(undefined` and fails if found outside `src/i18n`.
4. **The Italian catalog still loading when the UI first paints.** Switching to Italian must not flash English or render `undefined`. Task 1 tests that `useT()` keeps the English catalog until the Italian import resolves and that no rendered text contains `undefined`.
5. **Teams without gender after the deploy.** Old team docs have no `gender`; reads must default to `mixed` and saving the team form must require a choice. Task 4 pins both.

### Task 1: i18n core — catalog types, locale resolution, `useT`, flag

**Files:**
- Create: `src/i18n/catalog.ts`, `src/i18n/en/index.ts`, `src/i18n/en/common.ts`, `src/i18n/it/index.ts`, `src/i18n/it/common.ts`, `src/i18n/locales.ts`, `src/i18n/I18nProvider.tsx`, `src/i18n/plural.ts`, `public/locale-init.js`
- Modify: `index.html` (load `/locale-init.js` next to `/theme-init.js`), `src/App.tsx` (wrap in `I18nProvider`), `tests/setupTests.ts` (force `en`)
- Test: `src/i18n/locales.test.ts`, `src/i18n/I18nProvider.test.tsx`, `src/i18n/plural.test.ts`

**Interfaces:**
- Produces:
  ```ts
  // locales.ts
  export type Locale = 'en' | 'it';
  export const ITALIAN_ENABLED = false;
  export const LOCALE_KEY = 'vcb.locale';
  export function resolveLocale(input: { stored: string | null; clubLocale: Locale | null; browser: readonly string[]; devParam: string | null; dev: boolean }): Locale;
  // catalog.ts
  export type Catalog = typeof import('./en').en;          // { common, … } grows per feature
  // I18nProvider.tsx
  export function I18nProvider({ children }: { children: ReactNode }): JSX.Element;   // reads club locale from useAuth()
  export function useT(): Catalog;
  export function useLocale(): { locale: Locale; setLocale(l: Locale): void };
  export function getT(): Catalog;                          // for non-component code; same active catalog
  // plural.ts
  export function plural(locale: Locale, n: number, forms: { one: string; other: string }): string;
  ```
- Order (spec §3): stored → club locale → browser `it*` → `en`; any `it` result becomes `en` while `ITALIAN_ENABLED` is false, except `devParam === 'it' && dev`.
- `locale-init.js` sets `document.documentElement.lang` from `vcb.locale` (falls back to `en`), mirroring `theme-init.js` (external file, CSP `script-src 'self'`). The provider updates `lang` on change.

### Conversion recipe (Tasks 6–11)

For each folder in the task, one commit per folder:
1. Move every user-visible string (JSX text, `aria-label`, `placeholder`, `title`, `usePageMeta` titles, `useNotify` messages, `role="alert"` errors, button labels) into `src/i18n/en/<folder>.ts` **with identical English text**; interpolations and plurals become functions using `plural()`; gendered player wording takes `g`.
2. Replace them with `t.<folder>.<key>` from `useT()` (components) or `getT()` (non-components).
3. Pure modules that return messages return `{ code, params }` instead; the UI maps codes to catalog text. Update those modules' tests to assert codes in the same commit.
4. Add `src/i18n/it/<folder>.ts` (`satisfies Catalog['<folder>']`) using the spec §6 glossary.
5. Run `npx vitest run src/<folder>` (unchanged English assertions pass) and `npx tsc -b` (Italian complete). Commit `feat(i18n): <folder> in Italian`.
